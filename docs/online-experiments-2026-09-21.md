# 三个真实在线实验设计

状态：已于 2026-09-22 完成首轮及第二批在线执行。结果见 `online-experiments-results-2026-09-22.md` 和 `online-experiments-results-2026-09-22-batch-2.md`。

## 范围与基线

- 入口使用真实 `bin/cuhk-codex.cmd`，经过 Codex CLI → CCR → CUHK provider → OpenCLI → Chrome → 学校模型，再由 CLI 实际执行工具。交互操作使用真实 TUI；HTTP harness 只能辅助定位，不能替代 TUI 验收。
- 首轮固定当前配置 `glm5.3flash / high`，咨询关闭、Gateway 开启。记录 CLI 版本、代码版本及未提交改动摘要、实际运行服务路径/PID、浏览器状态、权限模式。CLI 显示名不作为实际模型证据。
- 现有记录已有在线 smoke，但 `live-progress.cjs` 的 20 秒命令由受控客户端驱动；真实 TUI steering、多会话隔离仍缺少验收。网页恢复中的空气泡/长思考部分仅有 DOM fixture 证据。
- 每个实验使用独立 run_id 和测试工作目录；仅发送合成数据。第一轮不混入切模型、重启服务或断网，以便归因。

## 共同观测与判定

执行前准备以下采集能力。现有日志不足以证明全链路对应关系；缺失字段需要增加可关闭的测试追踪，不能假定已具备。

| 观测点 | 必须记录 |
| --- | --- |
| CLI | 带时间戳的实际输入、TUI 输出/关键截图、stdout/stderr（适用时）、session/thread 标识、工具请求与结果、进程最终状态；输入被暂存或未实际提交也要记录 |
| Gateway | 请求/响应标识、客户端会话映射、bootstrap/delta、排队与拒绝、pending tool/call id、工具结果是否消费、repair/retry、HTTP/SSE 错误和终止、状态变化 |
| OpenCLI/网页 | 实际提交的测试 prompt、目标 tab/URL/可取得的对话标识、最新 user turn 后全部 AI 气泡、生成状态、原始回答及解析结果；无法取得持久标识时明确标为观测缺口 |
| 本地工具 | 启动次数、PID/process session id（与 Code Mode cell id 分开）、续读、stdout/stderr、退出码、文件内容和 SHA-256 |

统一记录 UTC 时间与单调时钟耗时，关联 run_id → CLI session → request → web turn → tool call → process。网页侧用现有 OpenCLI 路径的被动追踪/观测，避免额外并发控制器抢页面；采样忙时每 2–5 秒，关键提交/结束保留快照。健康状态只用于辅助，不能据此认定登录正常。

测试 prompt/结果可以完整落本地证据目录；不记录认证头、Cookie、Token 或无关历史。每轮输出时间线、断言表和失败前后证据。追踪缺失时判“证据不足”，不判通过。

统一结果：PASS（全部断言满足）、FAIL（有证据违反断言）、BLOCKED（登录/权限/额度等阻碍）、INCONCLUSIVE（证据或触发条件不足）。明确的并发拒绝可单独判“隔离通过、并发能力不支持”，不能计为并发成功。

## 实验 1：长命令期间的进度询问与追加要求

目的：检验真实 TUI 是否能把运行中的输入正确送达；长进程是否被重复启动、误报完成、丢失结果或锁死后续请求。

负载：预先在测试目录生成约 2,000 个合成小文件，扫描持续约 90 秒，每 5 秒输出一次扫描计数；混合少量 stderr 提示。用确定性节流保证跨越多次 10 秒 yield。脚本每次启动追加 launch 记录，结束才生成随机 receipt 和完成标记。只扫描测试目录；这覆盖 C 盘扫描的持续执行特征，不声称覆盖全盘权限、重解析点或真实目录规模。

步骤：

1. 在真实 TUI 请求执行扫描，并明确要求等待最终退出、返回 count 与 receipt。启动时记录 PID 和 launch 记录。
2. 看到第一条进度约 15 秒后，输入“现在进行到哪里了？继续原来的任务”。确认 TUI 实际受理方式和 Gateway 到达时间。
3. 约 30 秒输入“完成后把数量和 receipt 写入 summary.json”。记录它是即时送达、CLI 暂存还是 Gateway 排队。
4. 约 45 秒再询问一次进度，等待原任务结束，再发送一个短问题验证会话仍可用。

通过条件：只有一次启动；续读始终指向同一进程；收到 exit 0 后才宣称完成；文件数量、receipt、summary.json 与本地结果一致；追加要求恰好执行一次；不存在旧输出冒充新进度、409 锁死、未闭合请求。

时延分别测“按下发送→Gateway 到达”和“Gateway 到达→返回”。Gateway 收到进度请求后 2 秒内返回作为本轮验收目标；若 TUI 等到任务完成才提交，报告为 CLI 交互限制，不能把 HTTP 状态查询成功当作 TUI 成功。网页生成等待期间核对约 10 秒 SSE heartbeat；heartbeat 不证明本地进程有进展。

预算：约 5–10 分钟，硬上限 15 分钟。超时先保存证据，再停止本轮测试进程并确认页面/请求状态，禁止直接重发整个任务。对持续时间不足的扫描判触发不足。

## 实验 2：文件创建、失败修正与多轮上下文

目的：检验文件是否真的写入、旧工具结果是否重复消费、增量对话是否丢条件，以及 shell/script/patch 内容是否损坏。

负载：同一真实 CLI 会话内 8 轮，累计约 12–20 KB 合成上下文；每轮等待结束后再提交下一轮。工作目录包含空格与中文；文件内容包含中文、引号、反斜线、美元符号和代码块，全部作为数据处理。

步骤：

1. 提供唯一 case_id、输出路径规则、保留字段约束，要求创建结构固定的 JSON 文件。
2. 要求读回文件，返回实际字节数与本地计算的 SHA-256；独立校验器复核。
3. 追加一段合成需求说明，要求修改一个字段并保留 case_id 与其余字段。
4. 让模型运行预置验证器；验证器对已知的 fixture 状态返回 exit 7 和固定纠正提示。任务明确要求读取错误、修正指定字段并重跑验证器；预期最终 exit 0。
5. 加入第二段合成上下文，澄清并替换一个旧要求，检查新要求生效。
6. 要求修改带特殊字符的文本文件，逐字节与期望文件比较。
7. 只询问早期 case_id、保留约束和最近纠正要求，禁止读文件；验证网页会话记忆。只核对这些事实，不要求回答措辞一致。
8. 要求读取最终文件并输出清单、校验状态和 hash。

通过条件：全部文件与预先独立计算的期望内容一致；预期失败明确回传并被纠正；旧 call id 不被重复消费；后续任务没有 duplicate_tool_result；正常过程保持同一个网页对话；bootstrap 不重复发送，用户增量和工具结果不丢不重；最终完成声明有执行证据。

每轮记录用户输入长度与网页实际提交长度，判断是否意外全量重放。工具协议 reminder 不算历史重复；工具调用和修复轮也计入网页消息映射。若提前触发 CLI 压缩，单独记录边界，不混作普通增量丢失。

预算：约 15–25 分钟，硬上限 30 分钟或 40 次网页提交，先到为止。此实验属于中等多轮上下文，不代表超长上下文上限验收。

## 实验 3：两个独立会话的竞争、隔离与交替续话

目的：查出共享活动网页造成的串话、错误拒绝、饥饿和会话映射失效。当前文档明确尚不支持安全的多网页会话并行，预期可能暴露能力缺口。

负载：两个真实 CLI 进程 A、B，独立 CLI 会话标识和目录，分别使用随机 A_nonce、B_nonce 与同名 result.json。禁止两者共享测试输出文件。两个进程不等同于派生子代理。

步骤：

1. A 发出包含 A_nonce 的任务，在本地运行约 60 秒的测试命令；确认它已启动。
2. A 尚未结束时启动 B，让它创建包含 B_nonce 的小文件并回报本地 hash。记录 B 被排队、明确拒绝，还是得到服务。
3. A、B 均进入稳定状态后，分别追加“读取本会话结果并报告自己的标记”。若 B 被拒绝，只在确认 A 已完成且 B 没有未知交付后做一次显式重试。
4. 按 A→B→A→B 交替续话，每轮写入自己的目录并核验自己的 nonce。即使请求不重叠，也检查活动网页切换后 delta 是否进入错误对话。

隔离硬条件：任何时刻 A 的网页回答、工具结果、文件或最终回复都不能含 B_nonce，反之亦然；请求不得误消费对方的 call id；两个任务不能被静默合并；错误必须送达对应客户端。

结果分级：

- 两者完成且隔离完整：并发验收通过，并报告实际是串行排队还是浏览器独立并行，不能只凭同时启动声称并行。
- B 明确被拒绝，A 正常完成，B 后续可恢复且未串话：隔离通过，并发需求未满足；记录客户端实际显示的错误，不接受只写“All target providers failed”而没有定位证据。
- 请求串话、工具结果混淆、静默丢失、A 结束后 B 仍无法恢复：缺陷。

预算：约 8–15 分钟，硬上限 20 分钟。发现首个串话立即保存证据并停止后续写入，避免污染扩大。此实验不额外手动切网页；双 CLI 的自然交替已经能检验活动会话问题。

## 执行顺序与交付

顺序为 1→2→3；并发实验最后运行，避免污染前两个实验的会话基线。预计首轮约 30–50 分钟，学校生成时间会影响总耗时；不是耗时保证。每个实验先跑一次，仅对失败/可疑边界定点复现一次，不扩大成压力测试。

每个缺陷报告附：实际行为、预期行为、最短复现步骤、run_id、CLI/Gateway/web/tool 四侧证据、初步责任层和置信度。区分模型未遵循指令、CLI 未提交或执行被权限拒绝、Gateway 状态机错误、OpenCLI 监听错误以及上游超时；没有证据时不指定根因。

观测器应先完成一次短请求的全链路关联校验；若无法采集真实 TUI 输入或网页消息，不开始对应验收，也不降级后仍称其通过。所有本轮证据存放本地 gitignored runtime 目录，文档只保存脱敏结论。本轮不运行测试，不改运行配置或既有实现。
