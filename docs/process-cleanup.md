# 控制面板“关闭”按钮新增清理进程功能

点击“关闭”或窗口右上角关闭按钮时，控制面板会结束本安装目录的
Gateway、Codex/Claude 启动器、客户端及其子进程，确认没有相关残留后再关闭窗口。
清理失败会显示错误并保留面板，便于重试。

点击任一 CLI 启动按钮会先清理上一轮进程，再初始化并启动新会话。
这也意味着切换客户端会结束此前通过该安装目录启动的客户端。
命令行 `bin\cuhk-gateway.cmd stop` 使用相同清理逻辑；状态文件缺失或服务
失去响应时仍会扫描清理，不再仅删除状态文件。

后台 Node 进程继承归属记录，供父进程意外退出后的清理使用。
记录只包含 PID、可执行文件路径和创建时间，位于被 Git 忽略的
`gateway/runtime-state/processes/`。清理时校验进程身份并检查完整进程树，
保护调用者及其祖先进程，不按 `node.exe`、`codex.exe` 等通用名称批量结束程序。
会话历史和个人配置不会删除。

Windows 验证包括：实际 Gateway 启动与面板关闭、重新启动后再次关闭、
两个启动器的初始化清理，以及父进程退出后的孤儿进程、完整子进程树、
失效 PID 记录和无关进程保护。自动回归入口为
`gateway/cuhk-provider/test/process-cleanup.test.cjs` 和 `app/test_settings_app.py`。

2026-10-18 本机验收：Provider/启动器 180/180，面板 15/15 通过。
真实 Gateway 的 Codex 初始化清理、Claude 初始化清理、两次实际面板关闭按钮
调用，以及管理进程崩溃且 control.json 缺失后的关闭，共五种场景均为
残留进程 0、残留监听端口 0；个人配置文件哈希保持不变。
